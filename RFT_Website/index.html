GRPO Objective Function

Group Relative Policy Optimization — the RL algorithm used to fine-tune this model

GRPO Clipped Surrogate Objective

What does this formula do in plain English?

For each question q, GRPO samples a group of G responses from the current model. Each response gets a reward (e.g. correctness). The advantage Â of each response is its reward minus the group average — so the model learns "this response was better (or worse) than the pack." The clipping term prevents any single update from being too large, keeping training stable. No critic network is needed — the group itself acts as the baseline.

Sampling

G  ·  Group Size

Number of independent responses sampled per prompt. Larger G gives a better reward baseline but costs more memory. Typical values: 4–16. This project used G = 8.

Policy Ratio

πθ / πθold

Ratio of the new policy probability to the old policy probability for each token. Values > 1 mean the new policy assigns higher probability to this token than before the update.

Advantage

Âi,t — Relative Advantage

Reward of response i minus the mean reward across the G group: Â = r_i − mean(r₁…r_G). Positive means this response was better than average; negative means worse.

Stability

clip(·, 1−ε, 1+ε)

Clips the policy ratio to the range [1−ε, 1+ε]. Prevents excessively large gradient steps. Default ε = 0.2, meaning the ratio stays within ±20% of 1.

Conservative Update

min(unclipped, clipped) · Â

Taking the minimum of the clipped and unclipped objectives creates a pessimistic bound. The policy can only benefit from a large ratio if the advantage is positive and the ratio is within the clip range.

KL Regularisation

β · KL(πθ ‖ πref)

An additional penalty (subtracted from the reward before computing advantages) that keeps the policy close to a frozen reference model. Prevents reward hacking. This project used β = 0.004.

Why GRPO instead of PPO?

PPO requires a separate critic (value) network to estimate baselines, roughly doubling GPU memory. GRPO replaces the critic with a group baseline: the average reward of G rollouts. This makes GRPO far more memory-efficient, enabling fine-tuning of large models on a single GPU — exactly the setup used here with Qwen2.5-3B on a single A100.

How one training step works

  1. Sample G responses — for each training prompt, generate G completions with temperature > 0 to ensure diversity (this project used temperature 0.8, G = 8).
  2. Score with reward function — each completion receives a scalar reward. Here: 1.0 if the arithmetic expression is numerically correct and uses exactly the given numbers, else 0.0.
  3. Compute group advantage — subtract the group mean reward from each individual reward: Â_i = r_i − mean(r₁…r_G). Optionally normalise by the group standard deviation.
  4. Compute policy ratios — for every token in every response, compute π_θ / π_θ_old using log-probabilities already stored from sampling.
  5. Apply clipped surrogate objective — take the element-wise min of the clipped and unclipped ratio times advantage, then average over tokens and responses.
  6. Subtract KL penalty — measure divergence from a frozen reference model and subtract β · KL from the objective to prevent the policy drifting too far.
  7. Backpropagate and update — standard gradient ascent (maximising the objective) via AdamW with gradient accumulation.

Frequently Asked Questions

Common questions about Reinforcement Fine-Tuning (RFT) and GRPO — click any question to expand

01 What is Reinforcement Fine-Tuning (RFT)? ▾
RFT is a training paradigm where a language model is improved using reinforcement learning (RL) signals rather than pure supervised labels. Instead of showing the model the "correct" answer and minimising cross-entropy loss, you let the model generate its own answers and then reward or penalise them based on a reward function. Over many steps, the model learns to produce outputs that score higher on the reward — without ever needing ground-truth completions.
02 What is GRPO and how does it differ from PPO? ▾
GRPO (Group Relative Policy Optimisation) is an RL algorithm introduced with DeepSeek-R1 that replaces the PPO critic network with a group baseline. In PPO you need a separate value model (≈ same size as the policy) to estimate expected return. In GRPO you instead sample G completions per prompt and use their average reward as the baseline. This eliminates the critic entirely, cutting memory roughly in half while achieving comparable or better results on reasoning tasks.
03 Why use GRPO instead of supervised fine-tuning (SFT)? ▾
SFT requires labelled gold answers for every training example. For tasks like arithmetic, these are easy to generate — but for complex reasoning, code generation, or creative tasks, high-quality gold answers are expensive to produce. GRPO only needs a verifiable reward signal (e.g. "does this expression evaluate to the target?"), which can be fully automated. It also encourages the model to discover novel solution paths rather than memorising training examples.
04 What is a reward function and how do you design one? ▾
A reward function takes a model completion and returns a scalar score. Good reward functions are verifiable (not subjective), binary or sparse (correct = 1, else 0 works well), and not gameable. In this project the reward returns 1.0 if the expression: (a) uses exactly the three given numbers once each, and (b) evaluates to the target. Avoid using soft rewards like string overlap — they tend to reward superficial formatting rather than actual correctness.
05 What does the clipping parameter ε do? ▾
The clip range [1−ε, 1+ε] limits how much the probability ratio between the new and old policy can change in a single update. With the default ε = 0.2, the ratio is capped at ±20%. This prevents catastrophic policy collapse — where one lucky or unlucky gradient step destroys the model's language abilities. It's the key stability mechanism borrowed from PPO. Smaller ε = more conservative updates; larger ε = faster but riskier learning.
06 What is the advantage estimate Â and how is it computed in GRPO? ▾
In GRPO, the advantage for response i is: Â_i = r_i − mean(r₁…r_G), optionally divided by the group standard deviation. Every token in a correct response gets a positive advantage (the model is encouraged to make those tokens more probable), and every token in an incorrect response gets a negative advantage (those tokens are suppressed). The advantage is broadcast uniformly across all tokens in the response — GRPO does not assign per-token credit.
07 What is the KL penalty (β) and why does it matter? ▾
The KL penalty subtracts β × KL(π_θ ‖ π_ref) from each reward before computing advantages, where π_ref is a frozen copy of the initial model. This prevents reward hacking — where the model finds degenerate outputs that score high on the reward but are incoherent as language. A very small β (e.g. 0.004 as used here) barely constrains the model; a large β (e.g. 0.1) keeps it close to the original distribution. If you see repetitive or incoherent outputs, try increasing β.
08 How many group samples (G) should I use per prompt? ▾
Larger G gives a lower-variance baseline (better signal), but costs G× more GPU compute per step. For a 3B model on a single A100, G = 8 is a good default. If your reward is very sparse (e.g. correctness rate < 5%), consider increasing G so that at least one sample in the group is usually correct — otherwise every response has the same reward and gradients vanish (zero-advantage problem). If GPU memory is tight, reduce G and compensate with more gradient accumulation steps.
09 What does frac_reward_zero_std mean in the training logs? ▾
frac_reward_zero_std is the fraction of prompts where all G responses received the same reward (standard deviation = 0). When this happens, advantages are all zero and the gradient update is a no-op. High values (above ~30%) indicate the task is either too easy (all correct) or too hard (all wrong) for the current model. If too high, try harder prompts (too easy) or reduce the task difficulty / increase G (too hard).
10 Why use temperature > 0 during GRPO training rollouts? ▾
Temperature controls the diversity of the G rollouts. With temperature = 0 (greedy), all G responses would be identical — there's no variance, so advantages are all zero and nothing is learned. A temperature of 0.7–0.9 introduces enough diversity that some responses succeed and others fail, creating a useful learning signal. Note: this is a training hyperparameter. At inference time you should use temperature = 0 (greedy) for best accuracy on arithmetic tasks.
11 My model scores high during training but fails at inference — why? ▾
The most common cause is a prompt format mismatch. GRPO trains with a specific system prompt, user message format, and often an assistant prefill (e.g. <think>). If inference uses a different format, the model doesn't see the pattern it was trained on. Always use the exact same prompt template at inference. The second most common cause is temperature at inference: if you trained with greedy evaluation but your deployment uses sampling (temperature > 0), a small 3B model will make arithmetic errors.
12 What is the difference between the LoRA adapter and a merged model? ▾
LoRA adapter: a small set of low-rank weight matrices (a few hundred MB) stored separately from the base model. Loaded via PeftModel.from_pretrained(base, adapter_path) at inference. Merged model: the adapter weights are mathematically folded into the base model weights via merge_and_unload(), producing a single standalone model. Merged models are easier to deploy (no PEFT library needed) and are slightly faster, but produce identical outputs to the adapter version when loaded with the same dtype and decoding settings.
13 How do I know if GRPO training is actually working? ▾
Watch these metrics in order of importance: (1) rewards/accuracy_reward/mean — should trend upward over training. (2) frac_reward_zero_std — should stay below ~40%. (3) kl — should be small and stable (not exploding). (4) entropy — should decrease gradually (model becomes more confident). (5) grad_norm — large spikes indicate instability; consider clipping. If reward is flat and zero_std is high, the task is too hard for the model or your reward function has a bug.
14 Does adding a format reward (like requiring <think> tags) help? ▾
For small models (< 7B), mixing format and correctness rewards is often counterproductive. The model may learn to produce the right tags without solving the problem, or vice versa. The approach that works best (and was used here) is a single correctness reward: 1 if correct, 0 otherwise. The model naturally develops a reasoning format when the correctness signal is strong enough. Format rewards become more useful at 7B+ scale where the model has enough capacity to learn both simultaneously.
15 How much data do you need for GRPO fine-tuning? ▾
Surprisingly little. This project used only 400 training examples (from a 500-sample dataset, 80/20 split) and achieved a 50 percentage-point improvement over the base model in 2 epochs. GRPO is data-efficient because each prompt generates G rollouts — effectively 400 × 8 = 3,200 learning signal samples per epoch. The key is that the task must be verifiable (binary reward works) and the base model must already have some relevant capability that RL can amplify. GRPO won't teach a model something it has no prior knowledge of.
